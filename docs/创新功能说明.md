# 核心创新功能说明（公开证明子集）

> 本文说明本仓库公开的原创逻辑在完整产品中的作用，用于佐证版权归属与功能创新。
> 文中所有机柜、设备、SN、VLAN、机房名称均为虚构示例。
> **本仓库只公开核心逻辑的最小可运行证明子集，不含任何完整实现、UI、前端交互、三维渲染或静态资源。**

## 一、设备 ↔ 网络设备接口联动（双向）

设备详情里只要填「上联交换机 SN + 端口号」，系统会自动定位交换机、生成可读位置，并点亮对应端口；反向地，设备侧信息变化会同步回端口，设备下架则只熄灭自己占用的那一个端口。

| 触发 | 联动结果 |
|---|---|
| 新增 / 编辑设备，填上联 SN 与端口 | 自动定位交换机 → 端口点亮，回填对端、线缆、VLAN |
| 端口已被另一台设备占用 | 返回冲突，不静默覆盖 |
| 只改设备所属 VLAN | VLAN 自动同步到已关联的上联端口 |
| 设备下架 | 仅熄灭本设备占用的端口，不影响同交换机其他端口 |

证明子集：`lib/linkage.js`（逐字摘录自全量工程的联动实现，仅做脱离 HTTP 层的最小等价替换）。完整调用链见 `examples/linkage-demo.js`：

```bash
node examples/linkage-demo.js
```

自检覆盖：按 SN 定位 → 端口点亮 → VLAN 同步 → 冲突保护 → 下架回退，全部断言通过。

创新点在于**以设备为入口反向维护端口拓扑**，并用「端口对端归属校验」避免误伤：不是简单覆写端口状态，而是先确认链路确实属于该设备，才允许解除或覆盖，让机柜视图、设备详情与交换机端口面板三处数据始终一致。

## 二、导入时自动点亮（完整实现仅私有存证）

在导入「服务器详情表」时，系统会在落库的同时完成拓扑推导：按上联记录定位目标交换机、推断端口总数、把对应端口点亮并回填对端设备与线缆，实现「导入即成图」。**该完整实现未在本仓库公开**，仅由私有仓库 `IDC3D-full` 存证；本仓库只公开上面第一项的联动核心逻辑证明子集。

## 三、导入时临时指定柜名识别格式（示例推断）

真实机房的柜名写法千差万别：`A01`、`101 A14` 这类规则写法能自动识别，但 `101机房A01`、`A区01`、`1F-A01`、`A栋01` 这类带中文或特殊结构的写法往往识别不了，该机柜就被跳过。

本功能让用户**不用改代码、不用提需求**，直接在导入界面输入一个真实柜名示例（例如 `101机房A01`），系统按这个示例的字符结构临时推断出「房间号 / 列 / 序号」三个角色，再把同一结构套用到整批柜名上。

推断思路（详见 `lib/rack-format-public-demo.js`）：

```
把示例切成「数字段 / 字母段 / 固定文本段」
  → 最后一个数字段 = 序号
  → 序号之前最近的字母段 = 列
  → 列之前的所有字母 / 数字段 = 房间号前缀
  → 据此生成带捕获组的正则，供整批柜名复用
```

| 输入的示例 | 推断出的结构 | 能识别的同类柜名 |
|---|---|---|
| `101机房A01` | 房间号 + 列 + 序号 | `102机房B03`、`601机房A02` |
| `A区01` | 列 + 序号 | `B区05`、`C区12` |
| `1F-A01` | 房间号(1F) + 列 + 序号 | `2F-B12` |
| `A栋01` | 列 + 序号 | `C栋08` |

设计要点：

- **只对本次导入生效**，不写入配置、不影响以后的导入；
- **格式隔离**：不符合示例结构（如 `A01`）的柜名不会被误解析；
- **失败自动回退**：示例推断不出来或解析失败时，自动回退内置规则，不会比原来更差；
- **可读提示**：界面会显示「临时格式 → 按 房间号 + 列 + 序号 解析」，让用户确认没理解错。

证明子集：`lib/rack-format-public-demo.js`（示例推断核心算法；完整内置规则表未公开）。可运行自检：

```bash
node examples/rack-format-demo.js
```

自检覆盖：内置规则识别失败 → 示例推断 → 四类结构解析 → 格式隔离 → 回退逻辑 → 可读描述，全部断言通过。

**未公开**（由私有仓库 `IDC3D-full` 存证）：完整内置规则表（`A01` / `机柜A01` / `1号柜` / `第3柜` / `101 A14` / `A01-A02` 范围等全部写法）、导入落库与区域切分、U 位推断、设备列识别、批量处理、服务端路由与前端交互。
